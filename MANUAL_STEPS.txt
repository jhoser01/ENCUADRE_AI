PASO 1 — SUPABASE: Crear proyecto
═══════════════════════════════════════════════════════════════

Acción requerida: crear manualmente el proyecto Supabase (requiere login).

1. Abre https://supabase.com y entra con tu cuenta.
2. Haz clic en "New project".
3. Configura:
   - Nombre: encuadre-mvp
   - Database password: elige una contraseña fuerte y guárdala en un gestor de contraseñas
   - Región: South America (São Paulo) — la más cercana a Perú
   - Plan: Free
4. Espera ~2 minutos a que el proyecto esté listo.
5. Una vez listo, ve a: Project Settings → API
6. Copia los siguientes valores:
   - Project URL (parece: https://xxxxxxxxxxxxx.supabase.co)
   - Project API Keys → anon / public key
7. Ve a: Project Settings → API → Service Role key
   - Copia el service role key (SOLO server-side, NUNCA al frontend)

Después de completar este paso:
→ Crea el archivo c:\Users\jhose\OneDrive\Desktop\ENCUADRE\encuadre\.env.local con:
   NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxxx.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
   SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
→ Dile al agente: "Supabase está listo. Aquí está el Project ID: [ID]"
→ El agente aplicará las migraciones, RLS, buckets y seeds automáticamente.

IMPORTANTE: NUNCA pongas .env.local en Git. Ya está en .gitignore.

PASO 2 — AI PROVIDER: Obtener API Key (Gemini recomendado)
═══════════════════════════════════════════════════════════════

Opción A: Google Gemini (recomendado — gratuito para hackathon)
1. Abre https://aistudio.google.com
2. Haz clic en "Get API key" → "Create API key"
3. Selecciona tu proyecto de Google Cloud o crea uno nuevo
4. Copia la API key generada
5. Agrega a .env.local:
   AI_PROVIDER=gemini
   GEMINI_API_KEY=AIza...

Opción B: OpenAI
1. Abre https://platform.openai.com/api-keys
2. Crea una API key nueva con límite de USD $10 para la hackathon
3. Agrega a .env.local:
   AI_PROVIDER=openai
   OPENAI_API_KEY=sk-proj-...

PASO 4 — VERCEL: Crear proyecto y Deploy
═══════════════════════════════════════════════════════════════

Acción requerida: autorizar Vercel con GitHub (requiere OAuth).

1. Abre https://vercel.com/new
2. Importa el repositorio "encuadre" que creaste en el paso anterior
3. Framework: Next.js (detectado automáticamente)
4. Root directory: deja vacío (el proyecto está en la raíz)
5. En "Environment Variables", agrega TODAS las variables de .env.local:
   - NEXT_PUBLIC_SUPABASE_URL
   - NEXT_PUBLIC_SUPABASE_ANON_KEY
   - SUPABASE_SERVICE_ROLE_KEY
   - AI_PROVIDER
   - GEMINI_API_KEY (o OPENAI_API_KEY)
   - NEXT_PUBLIC_APP_URL = https://encuadre-[tu-proyecto].vercel.app (lo sabrás después del deploy)
6. Haz clic en "Deploy"
7. Copia la URL de producción generada por Vercel
8. Actualiza NEXT_PUBLIC_APP_URL en las variables de Vercel con la URL real
9. En Supabase → Authentication → URL Configuration:
   - Site URL: https://encuadre-[tu-proyecto].vercel.app
   - Redirect URLs: https://encuadre-[tu-proyecto].vercel.app/auth/callback

10. Dile al agente la URL de Vercel para actualizar README y docs.

═══════════════════════════════════════════════════════════════
PASO 5 — SUPABASE AUTH: Configurar email provider
═══════════════════════════════════════════════════════════════

Para que el registro/login funcione en producción:
1. En Supabase → Authentication → Providers → Email: ya está habilitado por defecto
2. En Authentication → Email Templates: puedes personalizar el email de confirmación
   (opcional para hackathon — el agente puede desactivar la confirmación de email)
3. Para desactivar la confirmación obligatoria de email (más simple para hackathon):
   Supabase → Authentication → Settings → "Confirm email" → OFF
   (Esto permite login inmediato sin verificar email)
